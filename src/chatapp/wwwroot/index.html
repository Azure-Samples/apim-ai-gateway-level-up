AI Gateway – Chat

Four ways to reach your models, each on its own tab. Tabs 1 & 2 call a model endpoint directly using two different API styles; tab 3 uses AIProjectClient + the project's Responses API; tab 4 uses a Foundry prompt agent. Point any endpoint at your APIM gateway URL (or, on tabs 3 & 4, use a BYOM <connection>/<model> model) to route traffic through the gateway.

Classic Azure OpenAI API. Calls the model with the well-established Azure OpenAI surface — /openai/deployments/<deployment>/chat/completions — where the deployment name lives in the URL. This is what most existing apps use today. Use the Deployment field below, and swap the endpoint for your APIM gateway URL to see the gateway in action.
Newer Azure AI model-inference API. Calls the same kind of model through the unified Foundry inference surface — /models/chat/completions — where the model name goes in the request body (not the URL). It's one route that works across many model types, not just OpenAI. Use the Model field below; the app appends /models automatically. Swap the endpoint for your APIM gateway URL to route through the gateway.
Agent-based access for bring-your-own-model (BYOM). Unlike the other two tabs, this doesn't call a model endpoint directly. It creates a Foundry prompt agent and chats with it through the project endpoint + Responses API. This is the only path that can use an admin-connected BYOM model (<connection-name>/<model-name>), and a successful reply proves the project endpoint routes inference through your APIM gateway on the backend (watch APIM analytics). Create an agent, chat, then delete it when done.
Project Responses API (via AIProjectClient). You supply only the project endpoint; chat goes through the project's OpenAI-compatible Responses API. Set Model to a plain deployment name for a direct call, or to a BYOM <connection-name>/<model-name> to route the response through your APIM gateway — no agent needed (watch APIM analytics). Check access confirms the project is reachable.
